## 2. 醒来第一件事

### 2.1 确认两个实例活着

计划任务会自动拉起，不用管。要确认就：

```powershell
Invoke-RestMethod http://127.0.0.1:8788/__health   # 生产 v1.1.0
Invoke-RestMethod http://127.0.0.1:8899/__health   # 开发 v1.2.0-dev
```

没起来就手动（各自目录里）：

```
%USERPROFILE%\.config\opencode\oc-error-monitor-v1.1.0\start-retry-proxy.bat --force
%USERPROFILE%\.config\opencode\oc-error-monitor-v1.2.0-dev\start-retry-proxy.bat --force
```

`--force` 会清掉 `stopped.by-user` 标记（你手动停过的实例会被它复活）。

### 2.2 确认客户端指向

```powershell
Get-Content $env:USERPROFILE\.config\opencode\retry-proxy-target.json
```

**现在的指向是 8899（开发版）**，44 个模型的 api 覆盖全是 `http://127.0.0.1:8899/v1`。

要指回生产（8788），**不需要动服务器**，一条命令：

```powershell
Invoke-RestMethod http://127.0.0.1:8899/__control -Method Post `
  -ContentType 'application/json' -Body '{"action":"point_client","port":8788}'
```

指回开发版：

```powershell
Invoke-RestMethod http://127.0.0.1:8899/__control -Method Post `
  -ContentType 'application/json' -Body '{"action":"point_client"}'
```

也可以在面板「设置 → 客户端指向」看当前指向和一致性，点按钮直接改。

## 6. 明天的方向

**先做受控的 429 归因实验**，不要继续加路由功能。

理由（E-012）：今天 12:00:33 走 direct（家庭宽带 IP）10 次全 429；12:04:53 走 proxy（Cloudflare 出口）9 次 429。**两条完全不同的出口，相隔 4 分钟都撞上限流。** 而今早 00:47–05:27 那段是 direct 197/213 成功、0 次 429，proxy 43 次 429。

所以「429 按出口 IP 记」是时段性现象，不是结构性的。这一版账本的价值落在 **403 与网络类失败** 上，不在 429。

实验设计：同模型、同一时段，direct 与 proxy 交替各 N 次，比较 429 率。

- 两条路接近 → 429 绑账号/模型/网关会话，杠杆在换模型（会话层 `session_failover` 已在做），路由到此为止
- 某条明显更差 → 429 确有出口成分，策略该去挑低限流出口

## 8. 几个容易踩的坑

- **不要用 PowerShell 的 `Get-Content` / `Set-Content` 改含中文的 UTF-8 文件**：ANSI 读入会毁掉中文，还会把 CRLF 变 LF（E-011）。用 edit/write 工具或 python 字节级处理。
- **节点名带 emoji**：PowerShell 控制台是 GBK，会乱码，连 URL 编码都会错 → 涉及 mihomo 控制器的一律用 python。
- **mihomo 组 `🎯 OpenCode专用` 是 8788 与 8899 共用的**：dev 路由器切节点会改变生产的出口。
- **旧生产进程的时钟曾经落后 3 小时**（旧进程特有）；新进程与机器时钟一致，日志时间可直接对齐。
- **429 面前换出口 IP 是徒劳的**（E-012），但 403 和网络类失败该换就换。
