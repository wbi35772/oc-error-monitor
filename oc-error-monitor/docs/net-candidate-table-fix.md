# 修 /__net 候选表与测速（v1.2.0-dev）

## 根因（已用证据确认）

1. **候选表只显示前 80 个** — `net_snapshot` 里
   `for name in (group_obj.get("all") or [])[:80]`。
   组 `🎯 OpenCode专用` 有 218 个成员，`all` 顺序是
   `🚀 节点选择` → `优选域名-01..N` → `多线/电信/移动/联通/IPv6优选` → DIRECT。
   最快的节点全在后段：多线-06=index 102、电信-25=171、联通-28=184 → 落在 `[:80]` 之外，
   **UI 里根本看不到，也点不到**。
2. **测速结果不完整且被误标** — mihomo `/group/{name}/delay` **只返回有响应的节点**，
   超时的节点被整体省略而不是标记为 timeout。同一组多次实测分别返回 48/52/58/60/62 个（候选 218）。
   现有 `net_probe` 因此报 `tested: 58`、`dead: 1`，把 160 个失败节点当成"没测"。
   逐节点测（218 个，24 并发，5s）27.8s 完成：53 存活 / 165 失败（504 超时）。
3. **UI 丢弃了不在前 80 里的测速结果** — `renderNet` 用 `n.members`（前 80）与 probe 结果做 map，
   落在前 80 之外的 ~41 个已测节点被直接扔掉。
4. **"优选"列永远显示"普通"** — 用户自己的 Clash 脚本 `Script.js` 用的正则
   `家宽|住宅|ISP|原生|WARP|MASQUE|Plus|US|美国|SG|新加坡|JP|日本` 在本订阅 218 个节点上**命中 0 个**
   （实际节点名是 优选域名-XX / 多线-XX / 电信-XX / 移动-XX / 联通-XX / IPv6优选-XX）。
   该列是死代码，"优选在前"排序也是空操作。

## 修法

- 后端 `net_snapshot`：`members` 返回**全部**成员（不再 `[:80]`），并把测速结果合并进每个成员。
- 后端 `net_probe`：改为**逐节点** `/proxies/{name}/delay`（有界并发 24），后台线程跑，
  进度可见（running/done/alive/dead），每个节点都有明确结论，不再有"没测"状态。
- 后端补 `family`（名称族：优选域名/多线/电信/移动/联通/IPv6优选），性质列显示族；
  保留用户脚本正则命中时的"优选"徽标（对别的订阅仍有效）。
- UI：候选表渲染全部行；排序 = 可用优先 → 实测延迟升序 → 未测；"只看可用"过滤；
  测速按钮改为启动 + 轮询进度，不再阻塞 30 秒。
- 切节点仍走 `/__net/switch`，行为不变。
