# E-003 · pick_route 从不写回账本：粘性永不生效

**severity**: high

## 观察

用假池子跑决策链，`current` 一直是 `None`：

```
attempt1 -> n1 strategy:least_fail | current = None
attempt2 -> n1 strategy:least_fail | current = None
报账 NET_CONNECT 后 current = None switches = 0
attempt3 -> n2 strategy:least_fail | current = None
attempt4 -> n2 strategy:least_fail
```

`current` 永远不写回，所以：

1. `sticky` 分支永远进不去（它要求 `current` 非空）。
2. 每次尝试都重跑策略。
3. 刚失败的成员因为落榜，下一次自然被跳过——**看起来像主动轮换，其实是无状态重挑**。
4. `switches` 恒为 0，没有任何地方报出异常。

真机上也一致：一次请求连撞四个节点，账本里四个成员各失败一次，但 `state.switches=0`。

## 修复

策略分支选定后写回：

```python
    # Without this the decision was recomputed on every attempt and the
    # strategy became an implicit round robin: each failure pushed the failed
    # member down the ranking, so the next attempt moved to a fresh node
    # whether or not that was wanted.
    _route_state["current"] = name
```

另外补了 `adopted` 分支：首次决策时若 mihomo 当前节点健康，就沿用它（换出口 IP 要付出所有在途会话的代价，没理由就换是不对的）。

## 修复后

```
attempt1 -> n1 adopted                current=n1
attempt2 -> n1 sticky                 current=n1
attempt3 -> n1 sticky                 current=n1
OK 之后 -> n1 sticky (仍然粘住)
```
