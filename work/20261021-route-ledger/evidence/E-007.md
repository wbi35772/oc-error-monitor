# E-007 · member_health 读路径建档，clear 看起来没生效

**severity**: medium

## 观察

`route_action` 的 `clear` 分支确实同时清了 `nodes` 与 `families`，但清完之后再读，`nodes` 又满了：

```
AssertionError: {'n1': {...}, ...} != {}
```

## 根因

`member_health()` 调 `_entry(name)`，而 `_entry` 在成员不存在时会**建一条新档**。`route_status()` 要遍历池里 218 个成员，于是每读一次面板，就建 218 条档。

后果有两个：

1. `clear` 之后立刻被读路径填满，看起来像没生效。
2. 账本里塞满从未用过的成员，「有记录 1」这种计数也失去意义。

## 修复

读路径改成只读：

```python
with _route_lock:
    # Read only. Routing status walks every member of a 218 node pool, and
    # creating a ledger row for each one turned "show me the ledger" into
    # "write 218 rows", which also made /__route's clear action look like
    # it had not worked.
    entry = _route_state["nodes"].get(name)
    if entry is not None:
        _decay(entry, now)
    else:
        entry = {}
```

只有 `report_route`（真正记账的地方）才建档。

## 回归测试

`test_route_policy.py::FamilyCooldown::test_clear_drops_families_too` 断言 clear 后 `nodes` 与 `families` 都是空的。

## 复现

```bash
python test_route_policy.py FamilyCooldown -v
```
