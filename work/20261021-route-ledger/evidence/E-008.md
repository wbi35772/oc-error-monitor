# E-008 · 生产 8788 重启后回到出厂设置（v1.1.0 无持久化）

**severity**: info

## 观察

生产 8788 被手动停止后重新拉起（`start-retry-proxy.bat --force`），恢复后：

```
生产 8788 起来了: pid=23096 ver=1.1.0 up=18s
  当前 force_route='' attempts=4
```

停止前是 `force_route=direct` / `attempts=10` / `timeout=120`。v1.1.0 没有持久化（E-001），所以全部回到默认。

必须手工补回：

```powershell
POST http://127.0.0.1:8788/__control {"action":"set","force_route":"direct"}
POST http://127.0.0.1:8788/__control {"action":"set","attempts":10,"timeout":120}
```

补回后探针请求正常：

```
ts=2026-10-21T11:52:52  route=direct  attempts=[IDENTITY]  ms=785
```

`IDENTITY` 是 FreeTierError（裸 curl 缺 opencode 客户端头），与代理无关。

## 附带发现：旧进程的时钟落后 3 小时

停止标记的内容时间与文件 mtime 差 3 小时：

```
{"at": "2026-10-21T08:43:52", "by": "switch", "pid": 14868, "port": 8788, "version": "1.1.0"}
文件 mtime: 2026-10-21 11:43:52
```

旧生产进程的日志时间戳也落后 3 小时（最后一条 `08:43:36`，而机器时间是 11:43）。新进程（pid 23096）写出的时间戳与机器时钟一致（`11:52:52`）。机器时区为 Eastern Standard Time (-05:00)，与用户此前 8788 停摆前观察到的「日志时间比机器时间早 3 小时」一致。

## 结论

这是 L0 要回移生产的直接理由（报告 P-005）：生产一旦重启，路由设置和重试耐心一起回到出厂值，而 429 会跟着回来。

## 复现

```powershell
$rt = Join-Path $env:USERPROFILE '.config\opencode\oc-error-monitor-v1.1.0'
Invoke-RestMethod "http://127.0.0.1:8788/__stats" | Select-Object -ExpandProperty settings
```
