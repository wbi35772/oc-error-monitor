# E-011 · 我自己用 PowerShell 破坏了 ui.html，并修复

**severity**: info

## 观察

改完面板的 class 之后，我用 PowerShell 做批量替换：

```powershell
$h = Get-Content ui.html -Raw
$h = $h.Replace('<section class="card">' + "`r`n" + '        <h2>路由决策</h2>', ...)
[IO.File]::WriteAllText((Resolve-Path "ui.html"), $h, (New-Object Text.UTF8Encoding($false)))
```

两个后果：

1. **中文变乱码**。PowerShell 5.1 的 `Get-Content` 默认按 ANSI 读文件，把 UTF-8 的中文读成乱码，再按 UTF-8 写回去。校验：`"路由决策" in text` → False。
2. **CRLF 变 LF**。仓库里 ui.html 的 blob 是 CRLF（`git show` 出来 782 个 CRLF），写回后变成 985 个裸 LF，diff 全是噪声。

替换本身也没生效：文件实际是 LF，我拼的是 `"`r`n`。

## 修复

1. 从运行目录那份（11:55 部署的、正确的）复制回仓库。
2. 用 python 字节级把 LF 转回 CRLF（`open(p,'rb')` → decode → replace → `open(p,'wb')`），不经过任何编码转换。
3. 后续所有 ui.html 修改改用 `edit` / `write` 工具（它们按 UTF-8 处理且保留换行风格），不再用 PowerShell 改这个文件。

## 教训

**同一批里，替换失败 + 编码损坏 + 换行损坏会同时发生**，而且 `Replace` 不报错、`WriteAllText` 不报错，只有下游渲染才暴露。改完必须校验：中文在不在、换行对不对、字节数变没变。

## 校验脚本（可复用）

```python
d = open(p, "rb").read(); t = d.decode("utf-8")
print(len(d), "路由决策" in t, t.count("\r\n"), t.replace("\r\n","").count("\n"))
```

## 复现

```powershell
# 反例，不要这样改 UTF-8 文件
$h = Get-Content x.html -Raw
[IO.File]::WriteAllText((Resolve-Path x.html), $h, (New-Object Text.UTF8Encoding($false)))
```
