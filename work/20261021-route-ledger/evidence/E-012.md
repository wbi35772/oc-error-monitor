# E-012 · 429 在两条路径上先后出现：限流键不在出口 IP

**severity**: high

## 观察

生产 8788 在 12:00 之后的真实请求（`deepseek-v4.1-flash-free`）：

| 时间 | 路径 | 出口 | 结果 | 耗时 |
|---|---|---|---|---|
| 11:52:52 | direct | 家庭宽带 IP | `IDENTITY`（我的裸 curl 探针） | 785ms |
| 12:00:33 | direct | 家庭宽带 IP | `RATE` ×10 | 204.7s |
| 12:04:53 | proxy | Cloudflare 共享出口 | `RATE`, `ERR:RemoteDisconnected`, `RATE` ×8 | 202.3s |

**相隔 4 分钟，direct 与 proxy 两条完全不同的出口，都撞上了 429。**

## 与今早的观测相反

00:47–05:27 那段（生产日志 294 条）：

| 路径 | 成功 | 429 |
|---|---|---|
| direct | 197/213 = 92.5% | **0** 次 |
| proxy | 55/81 = 67.9% | **43** 次 |

当时「direct 更稳、429 按出口 IP 记」的推断是成立的。但中午这条数据说明：

1. **direct 也会被限流**——家庭宽带 IP 一样撞 429。
2. **两条路同时被限**——不是「换 IP 就能躲开」。

## 含义

429 的限流键**不（只）在出口 IP**。更可能在账号 / 模型 / 网关会话这一层，出口 IP 是其中一个变量、甚至不是主变量。

这与仓库里早就记下的两件事吻合：

- README 的回测：403 视为瞬态；**模型差异远大于节点差异**（换模型 8/8，换节点 33–83%）。
- 会话层（`session_failover.py`）处理的 `AUTH_IP_REPUTATION` 走的是**换模型**，不是换节点。

也就是说，「多路出口、失败就换」这一整套的价值落在**403 与网络类失败**上（那部分确实该换 IP），而不是 429。429 面前，换出口 IP 是徒劳的。

## 另一条观察

12:04:53 那次 proxy 请求里混进了一个 `ERR:RemoteDisconnected`：中转连上了但连接被断开。说明 Cloudflare 中转此刻也不完全健康——这正是本版账本能处理的类型（`NET_STREAM` → 冷却该成员 → 换下一个）。

## 待做的受控实验

同模型、同一时段、direct 与 proxy 交替各 N 次，比较 429 率。这能把「时段性」和「出口相关」分开：

- 若两条路 429 率接近 → 429 绑账号/模型，路由在 429 上无用，杠杆在换模型。
- 若某条路明显更差 → 429 确有出口成分，策略应挑低限流出口。

这正是报告里的 P-007。

## 备注：生产的设置已被手动改过

用户在面板上把生产改成 `attempts=3` / `timeout=10` / `force_route=proxy`（本轮未动它）。12:00 那次请求耗了 204 秒，是 10 次重试 × 204s 累加的结果；改成 attempts=3 / timeout=10 之后最坏约 3×10s + 退避 ≈ 35 秒。

## 复现

```powershell
$log = Join-Path $env:USERPROFILE '.config\opencode\oc-error-monitor-v1.1.0\retry_proxy.log.jsonl'
Get-Content $log -Tail 6 | ForEach-Object { ($_ | ConvertFrom-Json) | Select-Object ts,route,attempts,ms }
```
