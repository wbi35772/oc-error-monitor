# E-013 · provider 级 api 对内置 opencode provider 无效

**severity**: high

## 观察

要把「切换实例」和「客户端指向」接起来，第一步是让客户端配置里**只有一处**端口，而不是 44 个模型各带一处 `provider.api`。

`https://opencode.ai/config.json` 的 `ProviderConfig` 确实提供了三个可能的位置：

| 位置 | schema |
|---|---|
| `provider.<id>.api` | `ProviderConfig.api` |
| `provider.<id>.options.baseURL` | `ProviderConfig.options.baseURL` |
| `provider.<id>.models.<model>.provider.api` | `ModelConfig.provider.api` |

于是做了个判别实验：**provider 级两个位置都指向 8788，只摘掉一个模型的 per-model 覆盖**（其余 43 个仍带 8899），然后用 opencode CLI 发一个真实请求。

结果：请求**两个代理都没收到**。

```
发请求前: 8788=714 条, 8899=26 条
$ opencode run --standalone -m opencode/deepseek-v4.1-flash-free "reply with the single word OK"
> build · deepseek-v4.1-flash-free
Error: Rate limit exceeded. Please try again later.
发请求后: 8788=714 条, 8899=26 条
  ==> 两个代理都没收到：请求绕过了代理（直连 opencode.ai）
```

那个 429 正是绕过代理直连 opencode.ai 得到的（和代理路径上的 429 同源）。

**结论：内置 `opencode` provider 的 provider 级 `api` 与 `options.baseURL` 都不生效。唯一有效的写法是每个模型各带一处 `provider.api`。**

（补充：第一次实验用 `opencode run`（不带 `--standalone`）时连两个代理也没收到，但那次走的是后台 opencode 服务的托管配置，不是用户配置，不能作为判别依据。`--standalone` 才是干净实验。）

## 由此确定的设计

端口不能作为常量住在客户端配置里，于是：

1. **端口只存在一处**：`~/.config/opencode/retry-proxy-target.json`，由**活着的实例自己写**（它知道自己的端口）。
2. **44 处 api 覆盖由一个写者统一改写**，改写只碰 `"api": "http://127.0.0.1:<port>/v1"` 这一种形状，其它服务的地址不动。
3. 改写后必须仍是合法 JSON，否则不写盘（坏配置不该被代理改坏）。
4. 状态文件由实例写，所以「客户端现在指向谁」是**可读回**的，面板能显示「一致 / 不一致」。

## 验证

- `test_client_pointing.py` 13 例：改写全部覆盖 / 不动别的服务 / 无覆盖不算错 / 坏文件不写 / 坏文件带覆盖要拒绝 / BOM 保留 / 幂等 / 状态文件读写 / 端口来自实例不来自调用方。
- 真机：`POST /__control {"action":"point_client"}` → 改了 44 处 → 状态文件写出 → `opencode run --standalone` 的请求**落在 8899**（+2 条），8788 一条没收到。
- 面板实测：卡片显示「一致」，按钮点击后 toast「客户端已指向 http://127.0.0.1:8899/v1（改了 44 处）」。

## 复现

```powershell
# 判别实验
$j = Get-Content "$env:USERPROFILE\.config\opencode\opencode.json" -Raw | ConvertFrom-Json
$j.provider.opencode | Add-Member -NotePropertyName api -NotePropertyValue 'http://127.0.0.1:8788/v1'
$j.provider.opencode.models.'deepseek-v4.1-flash-free'.PSObject.Properties.Remove('provider')
$j | ConvertTo-Json -Depth 10 | Set-Content "$env:USERPROFILE\.config\opencode\opencode.json"
opencode run --standalone -m opencode/deepseek-v4.1-flash-free "ping"
# 两个代理的日志条数都不变
```
